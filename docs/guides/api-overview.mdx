The Plytix API platform provides a suite of functionalities for managing your product content programmatically. It's built on standard REST principles and secured with bearer token authentication.

This lets you connect your own systems, such as an ERP or storefront, to your Plytix account with confidence, so you can sync, enrich, and distribute product data instead of managing it only through the dashboard.

## Core concepts

Before integrating with a specific resource, review these fundamental patterns. Understanding them up front will save you from surprises once you start building.

## Core concepts

**Resources.** The API is organized around resources — products, assets,
categories, attributes, relationships, and so on. Each resource defines its
own data, the operations available on it, and its relationships to other
resources.

**Resource-based URLs.** The API uses paths like `api/v3/<plural_entity_name>`,
with filters and pagination passed as query parameters (`_page`, `_page_size`,
`_sort_by`, and more), plus support for field-level operations, bulk
endpoints, and asynchronous job tracking.

List responses return results in a consistent shape:

```
"data": [],
"pagination": {
  "next_page": null,
  "previous_page": null,
  "filtered_count": 0,
  "total_count": 0
}
```

**Synchronous and asynchronous operations.** Some changes apply immediately
and return a result right away. Others — like bulk operations — are queued
and processed as a job that you check on separately, using a `process_id`
(or `bulk_job_id` for bulk operations) to track status. Which status code
you get back for a given change, and what it means, is covered in Status
codes and error codes.

PATCH is the recommended way to update entities. PUT is discouraged, since
it can unintentionally overwrite data you didn't mean to touch.

The API exposes the following resource areas:

- PDF Catalogs
- Import Profiles
- PIM Product Lists

**Automation**
- Bulk operations
