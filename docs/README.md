# Plytix Docs (Mintlify)

This directory is the Mintlify project root for the Plytix documentation site.
Navigation content is still scaffolding (one placeholder page), but branding
and the API reference are wired up for real.

- Run locally: `cd docs && npx mintlify dev`
- Config: `docs.json`
- `outline.md` (once generated by the `structure-planner` skill) will define the
  real navigation structure; `docs.json`'s `navigation.tabs[0]` ("Documentation")
  should be rebuilt from it. The "API Reference" tab is separate and already complete.

## Branding

Extracted from `materials/project-references/Plytix-Branding-Guidelines (2).pdf`
(vector paths pulled directly from the PDF, not hand-drawn):

- `docs.json` `colors`: primary `#7A52FF` (Purple Main), light `#BDA8FF` (Purple
  Medium). No dedicated "dark" shade exists in the guide, so primary is reused there.
- `favicon.svg` — the framed "Main icon" mark (purple square, white glyph), per
  the guide's "should be used by default" instruction.
- `logo/light.svg` / `logo/dark.svg` — the unframed wordmark lockup ("Main logo":
  glyph + "plytix" in Figtree Semibold), in the purple-on-light and white-on-dark
  variants shown in the guide's "Logo usage" page.
- `fonts.family: "Figtree"` — the brand's sole typeface, loaded from Google Fonts.
- Not yet applied: the glass-style card/blur treatment (page 6 of the guide) —
  no obvious Mintlify config hook for it; would need custom CSS if wanted later.

## API Reference

`api-reference/openapi.json` is a **copy** of the repo-root `openapi_pimv3.json`
(ground truth lives at the root — don't hand-edit divergences there), with two
additions the source spec lacks, sourced from `config/api-testing.config.md`:
- `servers`: `https://pim.plytix.com/api/v3` (per project materials; live
  reachability unconfirmed as of 2026-08-31 — see that config file)
- `components.securitySchemes.bearerAuth` + top-level `security`, describing the
  bearer-token flow (documented only in the v1 Postman collection, not in the spec)

If the root spec changes, re-copy it and reapply these two additions.

The rest of the repo (`materials/`, `bruno-collection/`, `config/`, `.claude/skills/`)
is engagement/research tooling, not part of the published site.

## Homepage decisions

`index.mdx` (`mode: "custom"`, served at `/`, deliberately **not** listed in
`docs.json`'s `navigation`) was generated via the `docs-homepage-kit`
plugin's `generate-docs-homepage` skill, first drafted 2026-09-02 against
`outline.md`'s full aspirational structure, then finished and re-grounded the
same day against the real `.mdx` pages that actually exist in `docs/guides/`
at time of writing (`overview`, `get-started-with-api`, `api-overview`,
`authentication`, `status-codes`, `rate-limits`) rather than the outline's
not-yet-built pages.

- **Pattern:** `minimal-hero-card-grid` — Plytix is a single product with no
  strong reason to lead with a live demo (`interactive-demo-hero`) or a
  brand/partner-ecosystem statement (`brand-marketing-hero`), and isn't
  genuinely multi-vertical (`multi-product-suite-hub`); the audience mostly
  wants fast routing into Get Started / API Reference, which is exactly this
  pattern's "use when."
- **Sections (`references/sections.md`, 11 candidates):** none used. No
  section's real "use when" content exists yet in this engagement (e.g. no
  sourced FAQ content for `dark-faq-accordion`, no confirmed MCP install
  command for `ide-tool-snippet-card`, no community channels found in
  materials for the pill-row/card-grid sections, SDKs aren't released yet so
  no code-forward resources panel). Per the skill, zero sections is the
  correct outcome here, not a gap.
- **Card illustrations (`references/cards.md`, 19 concepts):** none used.
  The 19 concepts are almost entirely payments/fintech-specific (tokenization,
  PIX, boletos, gateway, etc.) and don't describe a PIM product, so the whole
  group stays plain `<Card icon="...">`s per the all-or-nothing rule.
- **Trust row:** dropped entirely (not filled with placeholder text). The
  template's trust row needs a real latency/uptime/compliance-style claim
  from the corpus; `outline.md`'s Sources & Corrections explicitly flags that
  no rate-limit numbers or error-code list were found anywhere in the
  gathered materials, so there was nothing real to put there.
- **Hero copy:** kept to what `guides/overview.mdx` and `guides/get-started-with-api.mdx`
  already establish (connecting an ERP/storefront/internal tool to Plytix
  programmatically) — no invented marketing claims (throughput, adoption
  numbers, etc.).
- **Card routes point at real, existing pages**, not the outline's
  not-yet-drafted ones: "Get started" → `/guides/get-started-with-api`,
  "API reference" → `/guides/api-overview`. The third card intentionally
  isn't "Plytix MCP" (no MCP page exists yet, per the internal roadmap noted
  in `outline.md`) — instead it routes to the external Plytix Help Center
  (`https://help.plytix.com/en`), mirroring the audience split
  `guides/overview.mdx` already states explicitly ("This documentation is
  separate from the Plytix Help Center, which covers using the Plytix
  dashboard itself"). Revisit this card once an MCP page ships.
- **Colors:** primary `#7A52FF`, no separate accent used (this pattern only
  needs the primary). Company name and product name are both confirmed as
  "Plytix" (no distinct webhooks-hub label needed since this pattern has no
  webhooks card). Language: English, per all existing materials.
- **"Home" tab (2026-09-03):** added a `{"tab": "Home", "href": "/"}` entry
  as the first tab in `docs.json`'s `navigation.tabs`, per explicit request,
  so the custom homepage is reachable from the tab bar (previously only the
  external logo link went anywhere near "/"). This is a narrower case than
  the general "never list the custom page in navigation" rule in
  `generate-docs-homepage`'s `mdx-gotchas.md` — that rule is about listing
  `index` inside a tab's `groups[].pages` array, which drags the page into
  the standard sidebar/group system. A tab-level `href` is a plain link, not
  a page-list entry. Verified via a real `mint dev` render: the root page
  still carries Mintlify's `is-custom` CSS class, whose
  `peer-[.is-custom]:...:!hidden` rule hides the sidebar regardless of
  whether a tab points at "/" — confirmed present both with and without the
  Home tab, so this addition doesn't reintroduce the sidebar the rule warns
  about. All three tabs render, and `/`, `/guides/overview`, and
  `/guides/api-overview` all still return 200 with no server/console errors.
