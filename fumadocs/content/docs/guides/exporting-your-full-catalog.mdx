Pull your entire product catalog, with attributes, categories, and asset metadata included, without a separate call per product or per asset. This guide covers two ways to page through a large result set, expanding related data inline, and keeping a long export resumable: the pattern behind tools like catalog-production plugins and platform migrations. Here, full catalog means every product your request selects, with the fields you name. It doesn't include other Plytix resources, such as attribute definitions or product families, or the asset files themselves, so on its own it isn't a complete, restorable backup. All requests use the V3 API with a bearer token. Access tokens expire after 15 minutes, so a long export can start returning `401` partway through. If that happens, request a new token and resume from the page you were on.

## Prerequisites

Before you start, make sure you have the following:

- A bearer token. See [Authentication](/docs/reference/v3/authentication), or the [Quickstart](/docs/guides/quickstart) for a first walkthrough.
- An idea of which fields you actually need. Requesting only those fields keeps each page smaller and the export faster.

## Export the catalog page by page

Follow the steps below to request the fields you need, walk the pages until you reach the end, and read related data straight out of each product.

1. **Request the first page with the fields you need.**

   ```bash
   curl -G "https://pim.plytix.com/api/v3/products" \
     -H "Authorization: Bearer <access_token>" \
     --data-urlencode "_fields=id" \
     --data-urlencode "_fields=sku" \
     --data-urlencode "_fields=label" \
     --data-urlencode "_fields=attributes" \
     --data-urlencode "_fields=categories" \
     --data-urlencode "_fields=assets" \
     --data-urlencode "_sort_by=id" \
     --data-urlencode "_page_size=100"
   ```

   `_fields` accepts repeated values. Requesting `categories` or `assets` returns them fully expanded, with no separate call needed.

   Always set `_sort_by`. V3 has no default sort order, so without it the order of products across pages isn't defined. Sorting by `id` gives every product a fixed position. Including `id` in `_fields` lets you deduplicate your output, and switch to [keyset paging](#export-by-id-instead-of-page-number) if you need to.

   The default page size is 25 and the maximum is 1000. A bigger page means fewer requests, but each response is larger, takes longer to transfer, and costs more to repeat if it fails, more so with `attributes` and `assets` expanded. The examples use 100; adjust from there.

   Don't add `_expand`. The V3 search endpoint rejects it with `400` and `"Field '_expand' does not exist in model 'Product'."` Expansion happens automatically for each `_fields` value you name.

2. **Follow the `next_page` link until it stops appearing.**

   Every search response includes a `pagination` object:

   ```json
   {
     "data": [ /* ... */ ],
     "pagination": {
       "next_page": "http://pim.plytix.com/api/v3/products?_fields=id&_fields=sku&...&_sort_by=id&_page_size=100&_page=2"
     }
   }
   ```

   The link above is shortened. The real link repeats every filter, field, page size, and sort you sent on the first call, so request `pagination.next_page` as it is, after the scheme fix in the warning below. Continue while `next_page` holds a URL you can request, and stop when it's missing, `null`, or empty. Live responses leave the key out on the last page, and the `Pagination` schema also allows `null`, so check for both. The V3 search endpoint has no total count, so plan progress reporting around pages rather than a percentage. See [Pagination](/docs/reference/v3/pagination) for the full rules.

   Page numbers don't freeze the catalog. Each request runs the search again, so if a product is created, deleted, or changes its sort value while you're paging, the products after it shift by one position. One product can then be skipped or repeated at a page boundary. If the catalog is being edited during your export, use [keyset paging](#export-by-id-instead-of-page-number) instead.

   <Callout type="warn" title="Rewrite http links to https before you request them">
     Pagination links currently come back with the `http` scheme. That address `301`-redirects to `https`, and many HTTP clients drop the `Authorization` header across a scheme change, so the redirected request returns `401 {"detail": "Unauthorized"}`. Replace `http://` with `https://` before you request the link, and use it unchanged when it already starts with `https://`. This is a link-generation issue to be fixed, not a convention of the API. Don't work around it by letting your client forward the `Authorization` header across every redirect, which can send your token to a host you didn't intend.

     This bites hardest on a long export loop, where the first page succeeds and page two fails for no obvious reason.
   </Callout>

3. **Read categories and asset metadata directly from each product.**

   ```json
   {
     "id": "6a38f614c3d65a5f868b1a06",
     "sku": "BAG-10157",
     "categories": [{ "id": "...", "name": "Backpacks", "path": ["Website Taxonomy", "Bags & Luggage", "Backpacks"] }],
     "assets": [{ "id": "...", "filename": "BAG-10157_10.jpg", "content_type": "image/jpeg", "file_size": 559164, "path": "public_files/pim/assets/..." }]
   }
   ```

   Because `assets` returns each asset's metadata, such as its file name, type, size, and `path`, your export doesn't need a separate lookup per asset. It doesn't include the files themselves. `path` is where Plytix stores the file, not a download URL, so if you also need the files, plan that as a separate step.

4. **Scope the export if you don't need the whole catalog.**

   Combine `_fields` with a filter, for example to export only one category:

   ```bash
   curl -G "https://pim.plytix.com/api/v3/products" \
     -H "Authorization: Bearer <access_token>" \
     --data-urlencode "categories.name=Backpacks" \
     --data-urlencode "_fields=id" \
     --data-urlencode "_fields=sku" \
     --data-urlencode "_sort_by=id"
   ```

   See [Filtering and query syntax](/docs/reference/v3/filtering-query-syntax) for the other filters you can combine with `_fields`.

## Export by ID instead of page number

Keyset paging reads the catalog in `id` order and asks each time for the products after the last ID you received. A product created or deleted during the export no longer shifts the pages after it, so nothing is skipped or repeated at a page boundary. Use it for large exports while the catalog is being edited.

Follow the steps below to page through the catalog by ID.

1. **Request the first page sorted by `id`.**

   Send the request from step 1 of [Export the catalog page by page](#export-the-catalog-page-by-page) with `_page=1`. Keep `_sort_by=id` and `id` in `_fields`.

2. **Request the products after the last ID you received.**

   ```bash
   curl -G "https://pim.plytix.com/api/v3/products" \
     -H "Authorization: Bearer <access_token>" \
     --data-urlencode "id[gt]=6a38f614c3d65a5f868b1a06" \
     --data-urlencode "_fields=id" \
     --data-urlencode "_fields=sku" \
     --data-urlencode "_sort_by=id" \
     --data-urlencode "_page=1" \
     --data-urlencode "_page_size=100"
   ```

   Take the `id` of the last product on the page and send the same request with `id[gt]=<last_id>` added. Keep `_page=1`: the filter moves you forward, so don't follow `next_page`, which points to page 2 of the narrowed results.

3. **Stop when `next_page` holds no URL.**

   A response without a usable `next_page` link is the last page, so no products remain after it.

Keyset paging keeps the traversal stable, but it doesn't take a snapshot of the catalog. A product edited after you've read it keeps the values you read, and a product deleted after you've read it stays in your export.

## Keep a long export resumable

A long export should survive a failed request or a stopped script without starting over. Check each page before you save it, save it so an interruption can't leave a half-written file, record where to continue, retry only the failures worth retrying, and pace requests under both rate-limit windows. The Python script below does all of this while following `next_page`, using the `requests` library:

```python title="export_catalog.py"
import json
import os
import random
import time
from email.utils import parsedate_to_datetime
from urllib.parse import urlsplit

import requests

BASE_URL = "https://pim.plytix.com/api/v3/products"
FIELDS = ["id", "sku", "label", "attributes", "categories", "assets"]
FILTERS = []                # extra query parameters, such as ("categories.name", "Backpacks")
STATE_DIR = "export"        # one file per page, plus the manifest
OUTPUT = "products.jsonl"   # the finished export, one product per line
# This export's share of your account's limits, as (requests, seconds).
# Every integration on the account draws from the same allowance.
LIMITS = [(20, 10), (2000, 3600)]
MAX_WAIT = 60               # longest pause in seconds; a longer one stops the run for later
MAX_ATTEMPTS = 5

MANIFEST = os.path.join(STATE_DIR, "manifest.json")
ALLOWED = urlsplit(BASE_URL)

session = requests.Session()
session.headers["Authorization"] = "Bearer <access_token>"


class Stop(Exception):
    """Stop the run. Rerunning the script resumes from the manifest."""


def checked_url(url):
    """Return the URL with https, or stop if it isn't the products search on the Plytix host."""
    parts = urlsplit(url)
    if parts.scheme == "http":
        parts = parts._replace(scheme="https")  # pagination links currently use http
    if (parts.scheme != "https" or parts.hostname != ALLOWED.hostname
            or parts.port not in (None, 443) or parts.username or parts.password
            or parts.path != ALLOWED.path or parts.fragment):
        raise Stop(f"Refusing to send the token to an unexpected URL: {url}")
    return parts.geturl()


def write_atomic(path, lines):
    """Write the lines to a temporary file, then swap it into place in one step."""
    temp = path + ".tmp"
    with open(temp, "w", encoding="utf-8") as f:
        f.writelines(lines)
        f.flush()
        os.fsync(f.fileno())
    os.replace(temp, path)


def page_path(number):
    return os.path.join(STATE_DIR, f"page-{number:06d}.jsonl")


def save_state(state):
    write_atomic(MANIFEST, [json.dumps(state)])


def load_state():
    if not os.path.exists(MANIFEST):
        params = [("_fields", name) for name in FIELDS] + FILTERS
        params += [("_sort_by", "id"), ("_page_size", 100)]
        first = requests.Request("GET", BASE_URL, params=params).prepare().url
        return {"pages": 0, "next_url": checked_url(first), "sent": []}
    try:
        with open(MANIFEST, encoding="utf-8") as f:
            state = json.load(f)
        valid = (isinstance(state.get("pages"), int) and state["pages"] >= 0
                 and isinstance(state.get("next_url"), (str, type(None)))
                 and isinstance(state.get("sent"), list))
    except (OSError, ValueError, AttributeError):
        valid = False
    if not valid:
        raise Stop(f"{MANIFEST} is unreadable. Delete {STATE_DIR} to start a fresh export.")
    for number in range(1, state["pages"] + 1):
        if not os.path.exists(page_path(number)):
            raise Stop(f"{page_path(number)} is missing. Delete {STATE_DIR} to start a fresh export.")
    if state["next_url"]:
        state["next_url"] = checked_url(state["next_url"])
    return state


def pace(state):
    """Wait until every window in LIMITS has room for one more request."""
    now = time.time()
    longest = max(seconds for _, seconds in LIMITS)
    state["sent"] = [t for t in state["sent"] if now - t < longest]
    wait = 0
    for limit, seconds in LIMITS:
        recent = [t for t in state["sent"] if now - t < seconds]
        if len(recent) >= limit:
            wait = max(wait, recent[-limit] + seconds - now)
    if wait > MAX_WAIT:
        raise Stop(f"Rate limit reached. Rerun the script in {wait:.0f} seconds.")
    time.sleep(wait)
    state["sent"].append(time.time())


def retry_after(response):
    """Return the Retry-After delay in seconds, or None if it's missing or invalid."""
    value = response.headers.get("Retry-After", "").strip()
    if value.isdigit():
        return int(value)
    try:
        return max(0.0, parsedate_to_datetime(value).timestamp() - time.time())
    except (TypeError, ValueError, IndexError, OverflowError):
        return None


def fetch(url, state):
    for attempt in range(MAX_ATTEMPTS):
        pace(state)
        wait = None
        try:
            response = session.get(url, timeout=60, allow_redirects=False)
        except requests.RequestException:
            response = None  # timeout or connection error: retry
        if response is not None:
            if response.status_code == 200:
                try:
                    return response.json()
                except ValueError:
                    raise Stop("The response isn't valid JSON. Rerun the script to retry the page.")
            if response.status_code == 401:
                raise Stop("401: the token expired. Get a new token and rerun the script.")
            if response.status_code == 429:
                wait = retry_after(response)
            elif response.status_code not in (500, 502, 503, 504):
                raise Stop(f"{response.status_code}: {response.text[:500]}")
        if wait is None:
            wait = random.uniform(0, min(MAX_WAIT, 2 ** (attempt + 1)))  # backoff with jitter
        if wait > MAX_WAIT:
            raise Stop(f"Asked to wait {wait:.0f} seconds. Rerun the script after that.")
        time.sleep(wait)
    raise Stop("Too many failed attempts. Rerun the script to resume.")


def read_page(page):
    """Return the page's products and next URL, or stop if the page has an unexpected shape."""
    if not isinstance(page, dict) or not isinstance(page.get("data"), list):
        raise Stop("The response has no data list. Rerun the script to retry the page.")
    for product in page["data"]:
        if not isinstance(product, dict) or not isinstance(product.get("id"), str) or not product["id"]:
            raise Stop("A product in the response has no id. Rerun the script to retry the page.")
    pagination = page.get("pagination")
    if pagination is None:
        pagination = {}
    if not isinstance(pagination, dict) or not isinstance(pagination.get("next_page"), (str, type(None))):
        raise Stop("The response has an invalid pagination block. Rerun the script to retry the page.")
    next_url = pagination.get("next_page")
    if not next_url:
        return page["data"], None  # the last page
    return page["data"], checked_url(next_url)


def write_output(state):
    """Merge the page files into OUTPUT, keeping the last saved copy of each product."""
    last_seen = {}
    for number in range(1, state["pages"] + 1):
        with open(page_path(number), encoding="utf-8") as f:
            for line_number, line in enumerate(f):
                last_seen[json.loads(line)["id"]] = (number, line_number)

    def latest_lines():
        for number in range(1, state["pages"] + 1):
            with open(page_path(number), encoding="utf-8") as f:
                for line_number, line in enumerate(f):
                    if last_seen[json.loads(line)["id"]] == (number, line_number):
                        yield line

    write_atomic(OUTPUT, latest_lines())
    print(f"Exported {len(last_seen)} products from {state['pages']} pages to {OUTPUT}.")


def main():
    os.makedirs(STATE_DIR, exist_ok=True)
    try:
        state = load_state()
    except Stop as stop:
        raise SystemExit(str(stop))
    try:
        while state["next_url"]:
            products, next_url = read_page(fetch(state["next_url"], state))
            number = state["pages"] + 1
            write_atomic(page_path(number), [json.dumps(p, ensure_ascii=False) + "\n" for p in products])
            state.update(pages=number, next_url=next_url)
            save_state(state)  # record the page only after its file is complete
    except Stop as stop:
        save_state(state)
        raise SystemExit(str(stop))
    try:
        write_output(state)
    except (OSError, ValueError, KeyError) as error:
        raise SystemExit(f"Couldn't merge the page files ({error}). Delete {STATE_DIR} to start a fresh export.")


if __name__ == "__main__":
    main()
```

The script handles each part of a long run this way:

- **Credential safety:** before it sends the token, the script checks that every URL it requests, including each `next_page` link and the URL saved in the manifest, uses HTTPS on the Plytix host and points to the product search. It rewrites a same-host `http` link to `https`, refuses any other host, port, path, or user name, and doesn't follow redirects, so the token is never sent anywhere else.
- **Page validation:** a page is saved only after its `data` list, each product's `id`, and its `pagination` block have the expected shape. A malformed page stops the run without writing anything, and the next run requests that page again.
- **Interruption-safe saving:** each page goes to its own file under `export/`, and `export/manifest.json` records the page only after that file is complete. Every file is written to a temporary file first and then swapped into place, so an interruption leaves the previous version or the new one, never half a line. The next run continues from the manifest. A missing or unreadable manifest or page file stops the run with a message rather than reporting a finished export.
- **Deduplicated output:** after the last page is saved, the script merges the page files into `products.jsonl` and keeps the last saved copy of each product `id`. A product can be saved twice when the catalog changes during the run or a page is requested again after an interruption. Delete `export/` and `products.jsonl` before you start a fresh export. For [keyset paging](#export-by-id-instead-of-page-number), save the last `id` instead of the URL.
- **Pacing for both windows:** `LIMITS` holds the requests allowed per 10 seconds and per hour, set here to the lowest standard pair in [Rate limits](/docs/reference/v3/rate-limits). Every integration on your account shares that allowance, so set `LIMITS` to the part this export may use. The manifest keeps the times of recent requests, so the next run still counts the requests made in the last hour. When the next request would have to wait longer than `MAX_WAIT`, the script saves its place, stops, and tells you when to rerun it.
- **Bounded retries:** timeouts, `429`, and `5xx` responses are retried up to five times. A `429` with a valid `Retry-After` header waits as long as the header says. Without one, the script waits a random time that grows with each attempt, up to `MAX_WAIT`. A `Retry-After` longer than `MAX_WAIT` stops the run so you can rerun it later. Whether V3 sends `Retry-After` hasn't been confirmed, so the script works with or without it. Any other error stops the script, because the request itself needs fixing. A `401` means your token expired: get a new one and rerun the script.

## Troubleshooting

Check the problems below if you run into issues while following this guide.

<Accordions type="multiple">
  <Accordion title={<>A field you asked for with <code>_fields</code> is missing from the response</>} value="fields-silently-dropped">
    If a field is missing from every product, check its name. Plytix rejects some unknown names with a `400` error but drops others with no error, so a typo can cost you the field silently. Check top-level names against the product schema in [Get a product](/docs/reference/v3/products/get_products_api_v3_products__identifier__get), and custom attribute names against your account's attribute definitions from [`GET /api/v3/product-attributes`](/docs/reference/v3/productattributes/search_product_attributes_api_v3_product_attributes_get). If the field is missing only on some products, the name is fine and those products have no value for it: an attribute with no value can be missing from a product's `attributes` map, and other unset fields can come back as `null`. A product's response shows only what that product holds, so don't use one as the list of fields that exist.
  </Accordion>
  <Accordion title={<><code>_fields=category_ids</code> returns 400 instead of the field</>} value="fields-ids-hidden">
    Any field ending in `_ids` is hidden from API responses, so this returns a `HiddenFieldError`. That's deliberate: Plytix doesn't expose the denormalized ID arrays behind its relationships. Ask for the expanded plural form instead, so `categories` rather than `category_ids`, and `assets` rather than `asset_ids`. The expanded form returns the full objects and includes the IDs you were after anyway.
  </Accordion>
</Accordions>
