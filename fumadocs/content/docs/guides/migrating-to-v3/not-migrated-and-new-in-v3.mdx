Not every V1 call has a V3 counterpart yet. This page lists the V1 endpoints missing from the current V3 contract, the entry points that are new in V3, and the slice of the API that V2 covers. It reflects the V3 OpenAPI dated 2026-10-02 and will change as V3 expands. Keep a legacy call wherever your integration needs a capability with no confirmed public V3 equivalent, and move everything else to V3. It's part of the reference set for [Migration overview](/docs/guides/migrating-to-v3).

Each entry below falls into one of these groups:

- **Legacy only:** documented in V1 and absent from the current V3 contract. Keep calling V1.
- **Alternative in V3:** V3 has no matching endpoint but does the job another way. Where that way isn't confirmed yet, the entry says so.
- **Planned:** described in Plytix's V3 design, but not part of the current V3 contract.

## V1 endpoints missing from the V3 contract

All six endpoints below remain documented in the [V1/V2 reference](/reference/v1-v2/api-v1-v2-reference), and none of them is in the current V3 contract.

| V1 endpoint | Status | What to do |
|---|---|---|
| `PUT /api/v1/assets/{asset_id}/content` | Legacy only | Keep on V1. V3 takes a file only when it creates an asset. An asset update changes `filename` and `alt_text`, not the file. |
| `POST` and `DELETE /api/v1/products/{product_id}/assets[/{asset_id}]` | Alternative in V3 | V3 has no product-to-asset link path. You set a media or media gallery attribute to the asset ID with `PATCH /api/v3/products/{identifier}/attributes/{label}` and clear it with `DELETE` on the same path, and `thumbnail_id` sets the main image. A media attribute takes a bare asset ID and a media gallery attribute takes an array of IDs; objects such as `{"id": "<asset_id>"}` are rejected. Clearing the attribute doesn't delete the asset. See [Connect other assets to a product](/docs/guides/safely-removing-categories-assets-or-relationships#connect-other-assets-to-a-product). |
| `GET /api/v1/filters/product`, `/filters/asset`, `/filters/relationships` | Alternative in V3, partial | `GET /api/v3/product-attributes` returns your product attribute definitions, including each attribute's `type`. It doesn't list system fields, asset or relationship fields, or the supported operators: see [Filtering and search](/reference/v3/filtering-and-search) for those. Keep on V1 if you need the full list from the API. |
| `POST /api/v1/products/{parent_product_id}/variants/resync` | Legacy only | Keep on V1. |
| `POST /api/v1/accounts/api-credentials/search` | Legacy only | Keep on V1. You can manage API keys in the Plytix dashboard under the **API** tab, but that doesn't replace searching them through the API. |
| `POST /api/v1/accounts/memberships/search` | Legacy only | Keep on V1. You can manage users in the Plytix dashboard, but that doesn't replace searching them through the API. |

## Bulk operations

The current V3 contract has no bulk create, update, or delete endpoints. Bulk endpoints are part of Plytix's V3 design (planned), but there's no V3 bulk call to migrate to yet. To change many products in V3, send single-item requests paced under your [rate limit](/reference/v3/rate-limits).

## New entry points in V3

These V3 entry points have no V1 path of their own. One is a new resource. The other three are new top-level views of associations that V1 already managed under families and products. The list isn't exhaustive; see the [V3 API reference](/reference/v3) for every resource.

| V3 entry point | What it is | Managed through |
|---|---|---|
| `/api/v3/asset-lists` | A new resource: saved asset lists | Its own endpoints |
| `/api/v3/family-attributes` | A view of family-to-attribute associations and their levels. Narrow it with `product_family_id` | Read-only here. Link, change, and unlink attributes through `/api/v3/product-families/{product_family_id}/attributes` |
| `/api/v3/product-relationships` | A view of product relationship records: which products link to which relationship | Read-only here. Manage them through `/api/v3/products/{product_id}/relationships` |
| `/api/v3/related-products` | A view of related-product entries, including `quantity` and an optional expanded `product` | Read-only here. Change them through `/api/v3/products/{product_id}/relationships/{relationship_id}` |

## What V2 covers

V2 is a products-only beta served from the same base URL. It covers a subset of the V1 product endpoints. Its `DELETE /api/v2/products/{product_id}/relationships/{relationship_id}` removes products from a relationship, the same job V1 does with `/api/v1/products/{product_id}/relationships/{relationship_id}/unlink`, so it's a different route rather than a new capability. Everything outside products, including assets, attributes, categories, families, and relationship definitions, stays on V1.
