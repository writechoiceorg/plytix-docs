Produce a feed for one marketplace or retailer, for example a UK-only product file, by reading a filtered product set from Plytix and shaping it in your own integration. This guide covers mapping the marketplace's fields to Plytix fields, requesting and paging through the products in scope, transforming them into feed rows, and delivering the file on your schedule. Your integration builds and delivers the feed: this guide doesn't create or configure a Plytix channel. If you'd rather have Plytix build and publish the feed, set up a channel in Plytix instead, as described in [Creating a channel](https://help.plytix.com/en/creating-a-channel) and [Managing channels](https://help.plytix.com/en/managing-channels) in the Help Center. All requests use the V3 API at `https://pim.plytix.com/api/v3`. See [Filtering and Query Syntax](/docs/reference/v3/filtering-query-syntax) for the filter rules and [Pagination](/docs/reference/v3/pagination) for paging.

## Prerequisites

Before you start, make sure you have the following:

- API access to your Plytix account. How you get a token depends on the API version: V1/V2 exchange your API Key and password for a bearer token, as described in [Authentication](/docs/reference/legacy/token-authentication). V3 is moving to a new token-based authentication model whose details aren't published yet; see [Authentication and base URLs](/docs/guides/migrating-to-v3/authentication-and-base-urls). The examples below send the token as `Authorization: Bearer <access_token>`.
- The marketplace's feed specification: the fields it requires, their formats, and the file type it accepts.
- The attribute or category that defines which products belong in the feed. See [Filtering and Query Syntax](/docs/reference/v3/filtering-query-syntax).

## Generate the feed from product data

Follow the steps below to map the fields, read the products in scope, and turn them into a feed file.

1. **Map the marketplace's fields to Plytix fields.**

   Start from the marketplace's specification and note where each required field comes from in Plytix. The custom attribute names below are examples; use the ones in your account, which you can list with `GET /api/v3/product-attributes`.

   | Marketplace field | Plytix field |
   |---|---|
   | `sku` | `sku` |
   | `title` | `label` |
   | `gtin` | `gtin` |
   | `price` | `attributes.price` |
   | `category` | `categories` (each category's `path`) |

2. **Request the products in scope, with only the fields you mapped.**

   ```bash
   curl -G "https://pim.plytix.com/api/v3/products" \
     -H "Authorization: Bearer <access_token>" \
     --data-urlencode "attributes.market=UK" \
     --data-urlencode "_fields=id" \
     --data-urlencode "_fields=sku" \
     --data-urlencode "_fields=label" \
     --data-urlencode "_fields=gtin" \
     --data-urlencode "_fields=attributes" \
     --data-urlencode "_fields=categories" \
     --data-urlencode "_sort_by=id" \
     --data-urlencode "_page_size=100"
   ```

   `attributes.market=UK` is an example audience filter on a custom attribute. Filter on whatever defines your audience, such as a category with `categories.name=<category_name>`. `categories` returns each category fully expanded, including its `path`.

3. **Read every page and save the products.**

   Follow `pagination.next_page` while it holds a usable URL, and rewrite `http://` to `https://` before you request it. The script in [Keep a long export resumable](/docs/guides/exporting-your-full-catalog#keep-a-long-export-resumable) does this and saves each product as a line in `products.jsonl`. Add your audience filter to its `FILTERS` list, for example `("attributes.market", "UK")`, and set `FIELDS` to the fields you mapped.

4. **Transform each product into a feed row, and skip the ones that can't be listed.**

   ```python title="build_feed.py"
   import csv
   import json
   import os

   SOURCE = "products.jsonl"
   FEED = "uk_feed.csv"
   SKIPPED = "skipped.jsonl"
   COLUMNS = ["sku", "title", "gtin", "price", "category"]
   REQUIRED = ["sku", "title", "gtin", "price"]


   def to_row(product):
       attributes = product.get("attributes") or {}
       categories = product.get("categories") or []
       return {
           "sku": product.get("sku"),
           "title": (product.get("label") or "").strip(),
           "gtin": product.get("gtin"),
           "price": attributes.get("price"),
           "category": " > ".join(categories[0].get("path") or []) if categories else "",
       }


   # A resumed export can save the same product more than once. Keep the last saved
   # copy of each product, so the feed has one row per product id.
   rows, skipped = {}, {}
   with open(SOURCE, encoding="utf-8") as source:
       for line in source:
           if not line.strip():
               continue
           product = json.loads(line)
           row = to_row(product)
           rows.pop(product["id"], None)
           skipped.pop(product["id"], None)
           missing = [name for name in REQUIRED if row[name] in (None, "")]
           if missing:
               skipped[product["id"]] = {"id": product["id"], "sku": row["sku"], "missing": missing}
           else:
               rows[product["id"]] = row

   # Write to temporary files, then replace the old feed in one step.
   with open(FEED + ".tmp", "w", newline="", encoding="utf-8") as feed:
       writer = csv.DictWriter(feed, fieldnames=COLUMNS)
       writer.writeheader()
       writer.writerows(rows.values())
   with open(SKIPPED + ".tmp", "w", encoding="utf-8") as out:
       out.writelines(json.dumps(entry) + "\n" for entry in skipped.values())
   os.replace(FEED + ".tmp", FEED)
   os.replace(SKIPPED + ".tmp", SKIPPED)
   print(f"Wrote {len(rows)} rows to {FEED} and skipped {len(skipped)} products.")
   ```

   The script keeps the last saved copy of each product `id`, so a product that a resumed export saved twice still gets one row. It records every product it skips, with the fields it was missing, so you can fix them in Plytix. It writes both files under temporary names and replaces `uk_feed.csv` and `skipped.jsonl` only once they're complete, so a failed run leaves the previous feed in place. [Audit product data quality with filters](/docs/guides/auditing-product-data-quality-with-filters) shows how to find those products before you build the feed.

   If the marketplace needs image links, plan for them separately. The `assets` field returns each asset's metadata, including a `path` where Plytix stores the file, but `path` isn't a download URL.

5. **Deliver the file and refresh it on your schedule.**

   Upload or host the file the way the marketplace's specification requires. To keep the feed current, run steps 2 to 4 again on a schedule. Rebuilding the whole file each time is the simplest approach. To read only what changed, filter on `modified` as described in [Sync your ERP](/docs/guides/syncing-your-erp-with-plytix), and still rebuild in full from time to time, because a deleted product doesn't appear in a search.
