Produce a product set scoped to one channel, for example a UK-only feed or a Shopify-specific export, by combining a filtered product list with a channel. This guide covers creating and configuring a channel through the API and connecting it to the right products. All requests use the V3 API with a bearer token. See [Filtering and Query Syntax](/docs/reference/v3/filtering-query-syntax) for the filter rules and [Errors and Status Codes](/docs/reference/v3/errors-status-codes) for the error shapes. Creating a channel with a name that already exists returns `409`, and step 3 describes a `502` that looks like an outage but isn't.

## Prerequisites

Before you start, make sure you have the following:

- A bearer token. See [Authentication](/docs/reference/v3/authentication), or the [Quickstart](/docs/guides/quickstart) for a first walkthrough.
- The attribute or category you'll filter on to define the audience. See [Filtering and Query Syntax](/docs/reference/v3/filtering-query-syntax).

## Create the feed and connect it

Follow the steps below to build the product list, create the channel that reads from it, and schedule the rebuild.

1. **Build the product list your channel will pull from.**

   A channel doesn't filter products itself. It references a product list, so build that list first:

   ```bash
   curl -X POST "https://pim.plytix.com/api/v3/pim-product-lists" \
     -H "Authorization: Bearer <access_token>" \
     -H "Content-Type: application/json" \
     -d '{
       "name": "UK Feed",
       "type": "Smart",
       "query": [[{"operator": "eq", "field": "attributes.market", "value": "UK"}]]
     }'
   ```

   Save the returned `id`. You'll use it as `product_list_id` in the next step.

2. **Create the channel.**

   ```bash
   curl -X POST "https://pim.plytix.com/api/v3/channels" \
     -H "Authorization: Bearer <access_token>" \
     -H "Content-Type: application/json" \
     -d '{
       "name": "UK Marketplace Feed",
       "format": "CSV",
       "product_list_id": "<product_list_id>"
     }'
   ```

   `name` and `format` are the only required fields. The confirmed values for `format` are `CSV` and `XML`. Any other value returns `422` with `"Field format is unknown"`, and the error doesn't list the valid values, so other formats are unconfirmed. `product_list_id` is what actually connects your filtered products to this channel. A successful create returns `201` with the channel itself, not only its ID, which is worth reading: it shows the defaults Plytix filled in for everything you left out, including `active: false`, an `output_filename` of `plytix_feed`, and `UTC` as the build timezone.

3. **Set up a recurring rebuild, if the feed needs to stay current automatically.**

   ```bash
   curl -X PATCH "https://pim.plytix.com/api/v3/channels/<channel_id>" \
     -H "Authorization: Bearer <access_token>" \
     -H "Content-Type: application/json" \
     -d '{
       "rebuild_periodically": true,
       "rebuild_feed_frequency": "DAILY",
       "rebuild_feed_hod": 3,
       "rebuild_feed_moh": 0,
       "rebuild_feed_timezone": "UTC"
     }'
   ```

   For a `DAILY` schedule like this one, send all five fields together. `rebuild_periodically` on its own, or with only some of its companions, fails rather than falling back to a default.

   <Accordions>
     <Accordion title="Allowed schedule values">
       The spec allows these values:

       - `rebuild_feed_frequency` is one of `EVERY_3_HOURS`, `EVERY_6_HOURS`, `EVERY_12_HOURS`, `DAILY`, `WEEKLY`, or `MONTHLY`.
       - `rebuild_feed_hod` is 0 to 23.
       - `rebuild_feed_moh` is 0, 15, 30, or 45.

       The spec also defines two fields for weekly and monthly schedules:

       - `rebuild_feed_dow` is the day of the week.
       - `rebuild_feed_dom` is the day of the month, 1 to 31.

       Which of them each frequency requires is untested.
     </Accordion>
   </Accordions>

   A successful `PATCH` returns `204` with an empty body, so use the read-back in step 4 to confirm the schedule.

   <Callout type="warn" title="A partial schedule returns a server error, not a validation error">
     Omitting one of the companion fields returns `502` with `"There was an error processing your request. Please try again later"`. That reads like an outage but it's a bad request: check that `rebuild_feed_frequency`, `rebuild_feed_hod`, `rebuild_feed_moh`, and `rebuild_feed_timezone` are all present before retrying or escalating.
   </Callout>

4. **Confirm the channel picked up the right product list.**

   ```bash
   curl "https://pim.plytix.com/api/v3/channels/<channel_id>" \
     -H "Authorization: Bearer <access_token>"
   ```

   Check that `product_list_id` matches what you sent, and that `rebuild_feed_next_build` shows the schedule you expect.

## Build and publish the feed from the dashboard

The API configures the channel, and the dashboard builds and publishes the feed. Keep these limits in mind:

- **There's no way to assign products to a channel directly.** The only mechanism is `product_list_id`, pointing at a product list you build separately, as in steps 1 to 2. If you've read dashboard documentation describing direct product assignment to a channel, that's a UI-only path today.
- **There's no way to trigger the actual feed build or publish through the API.** Creating or updating a channel configures it, but the export file itself is still generated from the dashboard. Flipping `active` to `true` doesn't start a build.
