This page lists the AI assistants and agent frameworks expected to connect to the Plytix Platform MCP, and what each one would need in order to sign in.

## Compatibility requirements

A client is expected to be compatible with the Plytix Platform MCP when it can do three things: connect to a remote MCP server over HTTP, complete a sign-in to that server, and call tools.

{/* FLAG: Transport and authorization are unconfirmed (open):
  The transport and authorization method are assumed, not confirmed. No spec, endpoint URL, or protocol version has been shared. Confirm the following before publishing:

  - Is the Platform MCP served over HTTP at a public endpoint, and what is that URL?
  - Does it use OAuth, and which OAuth flow and protocol version? The authentication page notes that Plytix API authentication today is an API Key and password exchange.
  - Is a local (stdio) option offered as well?
*/}

| Requirement | What it means | Confirmed? |
|---|---|---|
| Remote HTTP transport | The client can register a server by URL, rather than running one on your machine | Not yet confirmed |
| Sign-in | The client can complete the authorization method the Platform MCP uses, which is not yet confirmed | Not yet confirmed |
| Tool calling | The model behind the client can call tools, not only read text | Not yet confirmed |

## Agent frameworks and SDKs

If you're building an agent rather than using an assistant, you would connect through an MCP client library.
