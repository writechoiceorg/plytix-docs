This page shows four illustrative workflows you could hand to an AI assistant once the Plytix Platform MCP is available, and what to check after each one. It assumes an assistant connected through the Platform MCP, a Plytix account with API access, and a role that allows the work. The Platform MCP authenticates and limits access in ways that are not yet confirmed, so see [Authentication and OAuth setup](/docs/guides/platform-mcp/authentication-and-oauth-setup) and [Permissions and security considerations](/docs/guides/platform-mcp/permissions-and-security). Every workflow here is a task the documentation already covers as code, so you can compare the two routes and pick whichever fits the job. Use a test account first, because some of these workflows change real data.

## Prerequisites

Before you start, you need:

- A Plytix account with data in it. These examples read and change real products, so use a test account first.
- An AI assistant connected to the Platform MCP. See [Supported clients](/docs/guides/platform-mcp/supported-clients) and [Authentication and OAuth setup](/docs/guides/platform-mcp/authentication-and-oauth-setup).
- Permission to write, for the examples that create or change data. Read-only access covers the first and third workflows only. See [Permissions and security considerations](/docs/guides/platform-mcp/permissions-and-security).

<Callout type="warn" title="Changes can't always be undone">
  An agent calling a write tool changes your catalog when it runs, and Plytix can't undo some changes, such as deletions. Ask for a plan before you ask for the change, and keep write access off the accounts you can't afford to have edited.
</Callout>

## How to read these examples

Each workflow gives you a prompt to adapt, the work the assistant does behind it, and a verification step. The prompts are starting points. Assistants vary, and a prompt that names the data you care about usually works better than a vague one.

## Audit product data quality

Find the products that are missing the attributes you care about, without writing a filter payload by hand. Follow the steps below to ask a question about the catalog and get an answer back.

1. **Ask for the gap, not the query.** Name the attributes and the scope:

   ```text
   Using Plytix, list the products in the Outdoor Furniture category that are
   missing a description, a primary image, or a GTIN. Group them by which
   field is missing and give me the SKUs.
   ```

2. **Review the filter the assistant used.** Ask it to show you the filter it built. Plytix supports OR logic and completeness filters that are underused because they're hard to discover, so this is worth reading once to learn the pattern.

3. **Verify a sample by hand.** Open two or three of the returned SKUs in Plytix and confirm the fields really are empty. If they aren't, the assistant likely filtered on the wrong attribute name.

4. **Ask for the fix as a separate step.** Don't combine the audit and the correction in one prompt. Get the list, check it, then ask for changes.

For the same audit as code, see [Audit product data quality with filters](/docs/guides/auditing-product-data-quality-with-filters).

## Curate a batch of products before importing them

Plytix stakeholders described curating data before importing it as a motivation for the MCP. Follow the steps below to bring product data from somewhere else, have the assistant clean it against your own catalog's rules, and create the products without building an integration first.

1. **Give the assistant the source data and the rules.** Paste or attach the raw data, then state what "correct" means in your catalog:

   ```text
   Here's a spreadsheet of 40 products from our supplier. Before creating
   anything in Plytix, check each row against our catalog: match the category
   names to existing Plytix categories, flag any SKU that already exists, and
   tell me which required attributes are missing. Don't create anything yet.
   ```

2. **Read the plan.** The assistant should come back with matched categories, duplicate SKUs, and gaps. Fix the source data or answer its questions before going further.

3. **Approve the write explicitly.** Only then ask it to create the products, and say how you want conflicts handled:

   ```text
   Create the 31 products that passed the check. Skip the duplicates.
   Assign each one to the category you matched earlier.
   ```

4. **Confirm the count.** Ask how many products it created and compare that number against your source. Then spot-check a few in Plytix.

<Callout type="info" title="Pace matters">
  In the V3 API, rate limits vary by account and are carried in your access token's claims. An assistant creating products one at a time can reach that limit on a large batch, which shows up as failures partway through. For large batches, see [Bulk operations for large catalogs](/docs/guides/bulk-operations-for-large-catalogs) and run it as code instead.
</Callout>

## Export a slice of the catalog

Pull a filtered set of products into a format you can hand to someone else, such as a marketplace listing sheet or a review document. Follow the steps below to export a slice.

1. **Describe the slice and the shape you want:**

   ```text
   Using Plytix, get every product in the Spring 2026 family that's marked
   ready for launch, with its SKU, title, price, and primary image URL.
   Give it to me as CSV.
   ```

2. **Check the row count against Plytix.** Run the same filter in the Plytix interface and compare totals. A mismatch usually means the assistant stopped at the first page of results rather than paging through all of them.

3. **Ask it to page explicitly** if the count is short:

   ```text
   That looks like only the first page. Page through all results and give me
   the complete set.
   ```

<Callout type="info" title="Channels are set up in Plytix">
  Channels (Shopify, BigCommerce, and feed exports) are configured in the Plytix interface. Whether channels can also be managed through the API is not yet confirmed. An agent can assemble the product set and check it before you send it.
</Callout>

For a fuller treatment, see [Export your full catalog](/docs/guides/exporting-your-full-catalog) and [Build a marketplace-specific product feed](/docs/guides/building-marketplace-specific-product-feeds).

## Clean up categories

Removing a category in Plytix can affect more than the one product in front of you, which makes it a good fit for an assistant that can check the impact first and a bad fit for an unsupervised one. Follow the steps below to check and scope a category removal.

1. **Ask what would be affected, before anything changes:**

   ```text
   Using Plytix, if I remove the "Clearance" category, which products lose it
   and do any of them have no other category left? Don't change anything yet.
   ```

2. **Read the impact list.** Products left with no category are the ones to handle deliberately.

3. **Scope the change narrowly.** Name the exact set rather than describing it loosely:

   ```text
   Remove the "Clearance" category from the 18 products you listed, except
   the three that would be left with no category at all.
   ```

4. **Verify in Plytix.** Confirm the count changed by exactly what you expected, and that the excluded products kept their category.

See [Safely remove categories, assets, or relationships](/docs/guides/safely-removing-categories-assets-or-relationships) for the rules behind this workflow, including which links can and can't be removed through the API.

## Troubleshooting

Check the problems below if a workflow doesn't go the way you expected.

<Accordions type="multiple">
  <Accordion title="The assistant answers about your catalog without calling Plytix" value="answers-without-calling">
    Numbers that look plausible but don't match anything in your account usually mean the assistant answered from its own knowledge instead of reaching for a tool. A client can skip calling a tool when the request doesn't make the need obvious, so name the source in your prompt, as in "Using Plytix, …", and ask it to cite the SKUs it retrieved. Naming the source in every catalog prompt helps prevent this.
  </Accordion>
  <Accordion title="A batch of writes stops partway through" value="batch-stops-partway">
    Ask which items the assistant completed before you retry anything, then retry only the remainder. Re-running the whole batch is what creates duplicates, and the agent has the list you need to avoid that. For large batches, run the job as code with paced requests rather than through an agent, as in [Bulk operations for large catalogs](/docs/guides/bulk-operations-for-large-catalogs).
  </Accordion>
  <Accordion title="Results are short and the totals don't match what Plytix shows" value="results-short-paging">
    An agent can stop at the first page of results and report that as the whole answer. Ask it to page through everything and compare the total again. Including the expected count in your prompt when you already know it gives the assistant something to check itself against.
  </Accordion>
  <Accordion title="The assistant changed something you didn't intend" value="unintended-change">
    Plytix can't undo some changes, such as deletions, so the route is forward: ask the assistant for the exact list of records it changed, then correct those. The discipline that prevents a repeat is the one every workflow on this page follows, which is splitting the work into a read prompt you review and a separate write prompt you approve, and granting write access only where the job actually needs it.
  </Accordion>
</Accordions>
