Plytix has two separate features for reacting to change: channel-processing webhooks, which notify you when an export finishes, and Automations, which apply rules to your product data as it changes. Neither is driven through the public API today. This page explains what each one does and where the API fits in now.

## What it is

**Channel webhooks** send a message to a URL you choose when a channel finishes processing, so you can trigger a next step (updating a downstream system or kicking off a Zapier or Make workflow) without polling. **Automations** are if/then rules that run inside Plytix itself: when a product matches a condition, an Automation changes or fills in data automatically, for example setting a default Brand value when one is missing.

These are unrelated features that happen to both live under the umbrella of "getting notified about change." Webhooks tell you something happened. Automations change data based on something happening. Don't conflate the two.

## How it works today

Both features are configured in the dashboard, and neither has an API you can call to set it up.

### Channel webhooks

You set up channel webhooks entirely in the dashboard, under a channel's settings. A basic webhook fires a fixed `POST` request with a fixed JSON payload (channel name, processing status, channel URL, feed URL, and the number of products processed) whenever that channel finishes processing. An advanced version of the same feature lets you customize the request URL, headers, and body.

<Callout type="warn" title="The channel API accepts a webhook payload and ignores it">
  The channel resource has a `webhook` field (`webhook_url`, `webhook_headers`, `webhook_body`), so it looks like you can configure a webhook through the API, but you can't. A `PATCH` carrying that field returns `204` as though it worked, but the value is discarded: a follow-up read shows the field absent, and requesting it with `_fields=webhook` returns nothing. Configure channel webhooks in the dashboard and treat the API field as unavailable.
</Callout>

### Automations

You set up Automations entirely in the dashboard, from the Automations section. You define a condition (for example, "Brand is empty and Category is Electronics") and an action (for example, "set Brand to TechCorp"). Plytix evaluates and applies these rules on its own as product data changes; there's no equivalent endpoint to create, read, or trigger an Automation through the API today.

## Where this leaves an integration today

If your integration needs to react to a channel finishing, use a dashboard-configured webhook, either basic or advanced, as described above. If your integration needs to react to a product changing for any other reason, polling with the incremental-sync pattern in [Sync your ERP](/docs/guides/syncing-your-erp-with-plytix) is the confirmed working approach.
