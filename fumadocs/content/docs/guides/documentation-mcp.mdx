The Plytix documentation runs a Model Context Protocol (MCP) server that lets an AI assistant search and read the public pages of these docs. Once it's connected, your assistant can look up endpoint names, parameters, and examples in the published pages instead of relying on what it already knows. Whether it uses the server for a given answer depends on your client and your prompt, so ask it to cite the page it used.

This guide covers connecting a client, verifying the connection, and what to do if your client doesn't support MCP. The server is read-only and needs no authentication. If your client can't connect to an MCP server, use the [llms.txt files](#use-llmstxt-if-your-client-doesnt-support-mcp) instead.

## Prerequisites

Before you start, make sure you have the following:

- An MCP-compatible client that supports remote servers over HTTP. Claude Code, Claude Desktop, Cursor, and VS Code all qualify.
- The Documentation MCP endpoint: `https://<docs-base-url>/api/mcp`.

You don't need a Plytix account, an API key, or a bearer token. The Documentation MCP searches and reads the public documentation only. Its tools can't access or change your Plytix account data. That applies to this server's tools: other servers or tools connected to your assistant keep their own capabilities.

## Add the server to your client

Pick your client below. In every case you're registering a single HTTP endpoint under a server name, and `plytix-docs` is a reasonable name to use.

<Tabs items={['Claude Code', 'Cursor', 'VS Code', 'Other clients']}>
  <Tab value="Claude Code">
    1. **Run** the `mcp add` command from your project directory:

       ```bash
       claude mcp add --transport http plytix-docs https://<docs-base-url>/api/mcp
       ```
  </Tab>
  <Tab value="Cursor">
    1. **Create or open** `.cursor/mcp.json` in your project, or `~/.cursor/mcp.json` to make the server available everywhere.

    2. **Add** the server entry:

       ```json title=".cursor/mcp.json"
       {
         "mcpServers": {
           "plytix-docs": {
             "url": "https://<docs-base-url>/api/mcp"
           }
         }
       }
       ```

    3. **Reload** Cursor, then confirm the server shows as connected under **Settings > MCP**.
  </Tab>
  <Tab value="VS Code">
    1. **Create or open** `.vscode/mcp.json` in your workspace.

    2. **Add** the server entry. Note that VS Code uses a `servers` key and needs an explicit `type`:

       ```json title=".vscode/mcp.json"
       {
         "servers": {
           "plytix-docs": {
             "type": "http",
             "url": "https://<docs-base-url>/api/mcp"
           }
         }
       }
       ```

    3. **Start** the server using the **Start** action VS Code shows above the entry in the file.
  </Tab>
  <Tab value="Other clients">
    Most clients accept the same JSON shape. Add the endpoint as a remote HTTP server, with no authentication:

    ```json
    {
      "mcpServers": {
        "plytix-docs": {
          "url": "https://<docs-base-url>/api/mcp"
        }
      }
    }
    ```

    In a desktop app, add it as a remote HTTP server through the app's settings instead.
  </Tab>
</Tabs>

## Verify the connection

1. **List the connected servers** in your client. In Claude Code, run `/mcp`. In Cursor and VS Code, open the MCP section of settings. You should see `plytix-docs` connected, exposing three tools.

2. **Ask a question that needs the docs.** For example: "Using the Plytix Documentation MCP, explain V3 product filtering and cite the relevant page." An answer that names a docs page, such as [Filtering and query syntax](/docs/reference/v3/filtering-query-syntax), shows the assistant used the server. An answer with no page cited may come from the model's own knowledge instead.

3. **Check reachability directly** if the client reports an error. This request confirms the endpoint exists and responds over JSON-RPC:

   ```bash
   curl -i -X POST https://<docs-base-url>/api/mcp \
     -H "Content-Type: application/json" \
     -H "Accept: application/json, text/event-stream" \
     -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}'
   ```

   A `404` means the URL is wrong. A JSON response that lists `search`, `list_pages`, and `get_page` means the server is up and answering. If your client still can't connect, check its configuration first: the transport type, the URL, and the key names in the config file. Opening the endpoint in a browser returns a short description of the server, including the MCP protocol versions it supports.

## What your assistant can do

The Documentation MCP exposes three tools. Your assistant decides when to call them, so you don't call them by name. Naming the Documentation MCP in your prompt and asking for the source page makes it more likely to use them, and lets you check the answer.

| Tool | What it does |
|---|---|
| `search` | Searches the docs for a query and returns matching pages |
| `list_pages` | Lists every docs page with its URL |
| `get_page` | Returns the full Markdown of one page, by URL |

Together, they help with questions that are slow to answer by hand, such as:

- "Which Plytix endpoints support filtering, and what's the filter syntax?"
- "Write a paginated export loop against the V3 products endpoint, following the pattern in the docs."
- "Does V3 have write parity with V1/V2 yet? Quote the page that says so."

## Use llms.txt if your client doesn't support MCP

Some assistants can read a URL but can't connect to an MCP server. The documentation publishes plain-text versions of itself for that case:

| URL | Contents |
|---|---|
| `https://<docs-base-url>/llms.txt` | An index of every page with its URL |
| `https://<docs-base-url>/llms-full.txt` | The full text of every page in one file |

Paste either URL into your assistant. To fetch one page instead of all of them, take its docs path and request it under `/llms.mdx`, ending in `/content.md`. This page, at `/docs/guides/documentation-mcp`, is served as Markdown at `https://<docs-base-url>/llms.mdx/docs/guides/documentation-mcp/content.md`.

## Troubleshooting

Check the problems below if you run into issues while connecting.

<Accordions type="multiple">
  <Accordion title="Your client shows the server as failed or disconnected" value="server-failed">
    Confirm the URL ends in `/api/mcp`, then open the endpoint itself in a browser. The docs site and the MCP endpoint can be up or down independently, so check the endpoint rather than the site. If it doesn't return its short description, the server is unavailable and the problem isn't in your client. If it responds but your client still fails, recheck the client configuration. Registering the server once at the user level rather than per project means you only have one URL to get right.
  </Accordion>
  <Accordion title="VS Code doesn't recognize the entry" value="vscode-format">
    VS Code's configuration format differs from Cursor's in two specific ways, and copying a Cursor snippet into `.vscode/mcp.json` trips both. The top-level key is `servers`, not `mcpServers`, and each entry needs an explicit `"type": "http"`. Fix those two and the **Start** action appears above the entry.
  </Accordion>
  <Accordion title="The assistant answers about Plytix without citing the docs" value="no-citation">
    Most clients only reach for a tool when the request makes the need obvious, so a bare question gets answered from the model's own knowledge instead. Name the source in your prompt, as in "Using the Plytix Documentation MCP, …", and ask it to cite the page it used so you can tell the difference.
  </Accordion>
  <Accordion title="The assistant can read pages but can't create or update products" value="read-only">
    That's expected. The Documentation MCP's tools search and read the published pages only. They have no access to your Plytix account, so they can't read or change your products.
  </Accordion>
</Accordions>
