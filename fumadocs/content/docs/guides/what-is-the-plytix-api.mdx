The Plytix API lets your own systems read and update the product content you manage in Plytix. This page explains what the API covers, who it's for, and where to start.

## What it is

The Plytix API is a REST API for the product data and assets in your Plytix account. You use it to connect your own systems, such as an ERP, a storefront, or an internal tool, to Plytix, so you can manage that content programmatically instead of only through the dashboard.

Plytix itself is a product content platform with several products that work together, such as Plytix PIM, Plytix DAM, and Plytix Feed Management. The API doesn't expose every part of that platform. It focuses on your catalog: the products, assets, and structure behind them.

## What the API covers

The public API covers your product catalog and the resources that organize it. The table below groups the main resources:

| Area | Resources |
|---|---|
| Product data | Products, product attributes, and product families |
| Catalog structure | Categories, relationships, and product lists |
| Assets | Assets, asset categories, and asset lists |

The V3 reference also documents other resources, such as channels and import profiles. For the full list, see the [V3 API reference](/reference/v3). If a feature you use in Plytix isn't in the reference, it isn't part of the public API yet.

## Who it's for

This documentation is for technical teams that connect Plytix to other systems. It's written for three kinds of readers:

- Integration engineers who connect Plytix to an ERP, storefront, or marketplace
- Automation builders who script repetitive tasks, such as catalog exports and data quality checks
- Partner developers who build products that integrate with Plytix for multiple customers

It's separate from the [Plytix Help Center](https://help.plytix.com/en), which covers using the Plytix dashboard itself: managing products by hand, configuring channels, and account administration.

## API versions

This documentation covers two versions of the Plytix API: V3 (Beta) and V1/V2 (Legacy). V3 is the newest version and the one to use for new integrations. It's in beta, so endpoints, fields, and behavior can change before its stable release.

V1/V2 remains available for existing integrations, and a few of its operations have no V3 equivalent yet. If you already have a V1/V2 integration, the Upgrade from V1/V2 guides help you decide what to move and how.
