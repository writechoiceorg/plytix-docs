Catch incomplete product data before it reaches a channel or marketplace: products missing an image, an empty description, or a field that was never filled in. This guide covers the filter operators that make these checks possible, and where the built-in completeness attributes can save you from writing the checks yourself. All requests use the V3 API with a bearer token. See [Filtering and Query Syntax](/docs/reference/v3/filtering-query-syntax) and [Pagination](/docs/reference/v3/pagination) for the full rules, and note that a search with no matches returns `data: []`.

## Prerequisites

Before you start, make sure you have the following:

- A bearer token. See [Authentication](/docs/reference/v3/authentication), or the [Quickstart](/docs/guides/quickstart) for a first walkthrough.
- Familiarity with the query-string filter syntax covered in [Filtering and Query Syntax](/docs/reference/v3/filtering-query-syntax). This guide assumes you can already build a basic filter like `sku=BAG-10157`.

## Find incomplete products

Follow the steps below to build the filters that surface missing fields, empty values, and low completeness scores.

1. **Find products missing a required field with `!exists`.**

   ```bash
   curl -G "https://pim.plytix.com/api/v3/products" \
     -H "Authorization: Bearer <access_token>" \
     --data-urlencode "gtin[!exists]=true" \
     --data-urlencode "_fields=id" \
     --data-urlencode "_fields=sku"
   ```

   Swap `gtin` for any field. `attributes.main_image_link[!exists]=true` finds products with no main image, and the same pattern works for any custom attribute, for example `attributes.short_description[!exists]=true`.

2. **Find products that do have a field set, with `exists`.**

   ```bash
   curl -G "https://pim.plytix.com/api/v3/products" \
     -H "Authorization: Bearer <access_token>" \
     --data-urlencode "attributes.main_image_link[exists]=true"
   ```

   Useful as a sanity check on the inverse of step 1, or to confirm how many products a required-field rollout still needs to reach.

3. **Catch empty values as well as missing ones with `length`.**

   `!exists` finds a field that has no value. To also catch empty values, check the length instead:

   ```bash
   curl -G "https://pim.plytix.com/api/v3/products" \
     -H "Authorization: Bearer <access_token>" \
     --data-urlencode "attributes.short_description[length]=0"
   ```

   This matches empty values and missing ones together, which is usually what a data-quality audit wants. Flip it to `[length][gt]=0` for the products that have real content.

4. **Search text case-insensitively with `contains:ignorecase`.**

   ```bash
   curl -G "https://pim.plytix.com/api/v3/products" \
     -H "Authorization: Bearer <access_token>" \
     --data-urlencode "attributes.short_description[contains:ignorecase]=waterproof"
   ```

   Use `[contains]` when case matters. Plytix accepts a fixed set of filter operators, and sending one it doesn't recognize returns `400` with the list of valid operators in the error message, which shows you what's available.

5. **Narrow an audit to a set of statuses with `in`.**

   ```bash
   curl -G "https://pim.plytix.com/api/v3/products" \
     -H "Authorization: Bearer <access_token>" \
     --data-urlencode "status[in]=Draft" \
     --data-urlencode "status[in]=Completed"
   ```

   Repeat the parameter for each value you want to match.

6. **Read the built-in completeness scores instead of writing your own checks.**

   Your account's completeness attributes appear in every product's `attributes` map alongside the values you set yourself, scored as numbers. Which ones exist depends on how your account is configured; a catalog set up for retail might carry `basic_information_completeness`, `website_ready`, and `marketing_ready`. Read one product to see yours:

   ```bash
   curl "https://pim.plytix.com/api/v3/products/<product_id>" \
     -H "Authorization: Bearer <access_token>"
   ```

   Filter on one of these the same way as any other field:

   ```bash
   curl -G "https://pim.plytix.com/api/v3/products" \
     -H "Authorization: Bearer <access_token>" \
     --data-urlencode "attributes.website_ready[gt]=90"
   ```

7. **Combine filters into one audit query.**

   Filters joined by `&` combine with AND. To match either condition, give each filter the same `_or[0]` prefix. For example, products with no main image or a `Draft` status:

   ```bash
   curl -G "https://pim.plytix.com/api/v3/products" \
     -H "Authorization: Bearer <access_token>" \
     --data-urlencode "_or[0]attributes.main_image_link[!exists]=true" \
     --data-urlencode "_or[0]status=Draft"
   ```

   See [Filtering and Query Syntax](/docs/reference/v3/filtering-query-syntax) for grouping rules. To reuse a filtered set of products, see step 1 of [Build a marketplace-specific product feed](/docs/guides/building-marketplace-specific-product-feeds), which creates a product list.
