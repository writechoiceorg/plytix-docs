      - content: >-
          Creates one product and returns the full record, including its new
          `id`. Only `sku` is required.


          The `sku` must be unique in your account. If a product with that SKU
          already exists, the request returns `409` and creates nothing. That
          makes a create safe to retry: if a request times out, sending it again
          either creates the product or returns `409`, never a duplicate.


          Set custom attribute values in `attributes`, keyed by each attribute's
          `label` (its snake_case name, not the display name), for example
          `{"attributes": {"collection": "2019"}}`. The response also lists the
          account's completeness attributes, such as `basic_info_complete`,
          which Plytix calculates for you.


          To create a variant, set `parent_id` to the parent product's ID:


          - The variant joins the parent's product family automatically, so you
          can leave out `product_family_id`. Sending a different family returns
          `422`.

          - The variant gets `product_level` `2`, and a parent that was
          standalone becomes `1`. A variant of a variant is `3`.


          See [Reconstruct parent/variant
          hierarchies](/docs/guides/reconstructing-parent-variant-hierarchies).


          The body accepts only the fields listed below. List fields such as
          `category_ids` and `static_list_ids` return `422` with "Extra inputs
          are not permitted". Link categories after the product exists, with
          [Link a category to a
          product](/reference/v3/products/link-product-category).
