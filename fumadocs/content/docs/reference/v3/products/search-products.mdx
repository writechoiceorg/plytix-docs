      - content: >-
          Returns the products in your account that match your filters, one page
          at a time. With no filters, it returns every product, including
          archived ones.


          Use it to look up products by SKU or any other field, to export your
          catalog page by page, or to find products that changed after a given
          date.


          Filters are query parameters written as `field=value` or
          `field[operator]=value`. A product must match all of them, unless you
          group filters with `_or`. Besides the top-level fields, you can filter
          on:


          - Custom attributes, through `attributes.<label>`, for example
          `attributes.brand=Plytix`

          - Related records, through dot paths such as `categories.name`

          - A parent's direct variants, through `parent_id=<id>` or
          `parent.sku=<sku>`


          A few filter details to plan for:


          - For a case-insensitive match, use `contains:ignorecase`. `icontains`
          isn't an operator and returns `400`.

          - A date filter with an invalid date, such as
          `modified[gte]=not-a-date`, returns an empty list instead of an error.


          Results come back 25 per page by default, up to 1000 with
          `_page_size`. To get the next page, follow `pagination.next_page`. On
          the last page that key is left out, not set to `null`. The link starts
          with `http://`, so change it to `https://` before you follow it.
          Otherwise the redirect can drop your `Authorization` header. The
          response doesn't include a total count.


          For a stable order while you page through a large result set, sort by
          `id`, which follows creation order. Each page is a separate request.
          See [Rate limits](/reference/v3/rate-limits).
