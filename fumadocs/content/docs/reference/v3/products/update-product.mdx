      - content: >-
          Changes the fields you send and leaves every other field as it is. A
          successful update returns `204` with an empty body. To see the result,
          read the product back.


          The `attributes` map is the exception: it's replaced as a whole. Any
          custom attribute you leave out of `attributes` is removed from the
          product. To change custom attributes, do one of the following:


          - Send the complete `attributes` map, with the values you want to
          keep.

          - Change one attribute at a time with [Update a product
          field](/docs/reference/v3/products/update-product-field), for example
          `PATCH /api/v3/products/{identifier}/attributes/material`.


          Completeness and formula attributes are calculated by Plytix. Values
          you send for them are ignored.


          Send `null` to clear a field:


          - `thumbnail_id: null` removes the thumbnail. If the thumbnail was the
          asset's only link to the product, the asset also leaves the product's
          `assets`.

          - `parent_id: null` detaches a variant from its parent. The product
          goes back to `product_level` `0`, loses the values it inherited, and
          keeps its product family.

          - `product_family_id: null` removes the product from its product
          family.


          `gtin` can't be cleared with `null`. A GTIN with an invalid check
          digit returns `422`.


          Don't send `product_family_id` in the same request as `parent_id`:
          sending both returns `422`.


          The body accepts only the fields listed below. You can't change `sku`
          here, and list fields such as `category_ids` and `static_list_ids`
          return `422`. See [Update and delete
          records](/docs/reference/v3/updates-and-deletes) for how PATCH works
          across the V3 API.
