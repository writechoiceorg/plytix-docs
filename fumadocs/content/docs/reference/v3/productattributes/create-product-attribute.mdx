          Creates one attribute definition and returns it, including its new
          `id`. Creating an attribute doesn't give any product a value for it:
          it makes the field available to products.


          `name` and `type` are required. `type` decides which other fields the
          body accepts. The request body schema below has one tab per type, and
          each tab lists that type's fields:


          | `type` | Holds | Extra fields |

          |---|---|---|

          | `TextAttribute` | Text | `character_limit` |

          | `HtmlAttribute` | HTML text | |

          | `IntAttribute` | A whole number | |

          | `DecimalAttribute` | A decimal number | |

          | `BooleanAttribute` | `true` or `false` | |

          | `DateAttribute` | A date | `include_time` |

          | `UrlAttribute` | A URL | |

          | `DropdownAttribute` | One of a list of options | `options`,
          `manual_sorting`, `sort_ascending`, `restricted` |

          | `MultiSelectAttribute` | Several of a list of options | `options`,
          `manual_sorting`, `sort_ascending`, `restricted` |

          | `MediaAttribute` | One asset | |

          | `MediaGalleryAttribute` | Several assets | |

          | `CompletenessAttribute` | A score Plytix calculates | `attributes` |

          | `FormulaAttribute` | A value Plytix calculates | `formula`,
          `formula_str` |


          A `type` that isn't in this table returns `422`, and the message lists
          the accepted values. You can't change `type` after the attribute
          exists.


          `label` is the attribute's key: products store their values for it in
          `attributes.<label>`, and filters use `attributes.<label>`. It must
          use lowercase letters, digits, and underscores only (`^[a-z0-9_]+$`);
          anything else returns `422`. The label can't be changed later, so
          choose it with care. If you leave it out, Plytix sets it from `name`.
          When `name` contains capitals or spaces, send `label` yourself.


          A successful create returns `201` with the new attribute in `data`. If
          an attribute with the same name already exists, the request returns
          `409` and creates nothing.


          Completeness and formula attributes hold values that Plytix calculates
          on each product. You configure them here, and products can't write
          their values: a value sent in a product's `attributes` map is ignored
          without an error.


          - `CompletenessAttribute`: list the attributes it scores in
          `attributes`, each as `{"id": "<attribute_id>"}`. A list of plain ID
          strings returns `422`.

          - `FormulaAttribute`: each account can hold a limited number of
          formula attributes. When you reach the limit, the request returns
          `422` with "This account reached the limit of ... formula attributes".
          Ask your account manager if you need a higher limit.


          The body accepts only the fields of the chosen type. Group membership
          isn't set here: `group_ids` returns `422` with "Extra inputs are not
          permitted".
