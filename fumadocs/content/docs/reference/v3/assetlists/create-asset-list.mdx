      - content: >-
          Creates one asset list and returns it, including its new `id`. `name`
          and `type` are required.


          - For a `Smart` list, send a `query`. The list's members are the
          assets that match it.

          - For a `Static` list, leave `query` out. Membership is stored on each
          asset. Plytix generates the list's `query`, which points at the list's
          own ID.


          A `query` is a list of groups, and each group is a list of conditions.
          An asset is in the list when it matches every condition in at least
          one group. Each condition names a `field`, an `operator`, and a
          `value`, for example `{"field": "extension", "operator": "eq",
          "value": "jpg"}`.


          The operators in a `query` aren't the same as the search filter
          operators. For example, `like` works in a `query` but not as a search
          filter. `FilterOperator` in the request body lists the operators the
          spec allows. `eq`, `like`, `in`, and `!exists` have been confirmed.


          A successful create returns `201` with the new list. Each condition
          comes back with a `field_type` key added. A body without `name` or
          `type` returns `422`, with one entry in `errors` for each missing
          field. A list name that's already in use returns `409`.
