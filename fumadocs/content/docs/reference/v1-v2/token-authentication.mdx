The V1/V2 APIs use bearer token authentication. Rather than sending your API key and password with every call, you exchange them once for a short-lived access token, then send that token in the `Authorization` header of every request. Any administrator on your Plytix account can issue the API key and password from the **API** tab in the account's Admin section.

This page documents the token exchange and how to use the token you get back.

## Get a bearer token

To get a token, send your API key and password as the request body. Both fields are required:

| Field | Type | Required | Description |
|---|---|---|---|
| `api_key` | string | Yes | The API key generated from your account's API tab. |
| `api_password` | string | Yes | The API password generated alongside the key. |

Here's the full request and the response you get back:

<Tabs items={['Request', 'Response']}>
  <Tab value="Request">
    ```bash
    curl --request POST \
      --url https://auth.plytix.com/auth/api/get-token \
      --header 'Content-Type: application/json' \
      --data '{
        "api_key": "your.api.key",
        "api_password": "your.secret.api.password"
      }'
    ```
  </Tab>
  <Tab value="Response">
    ```json
    {
      "data": [
        {
          "access_token": "your_access_token"
        }
      ]
    }
    ```
  </Tab>
</Tabs>

The token request goes to the authentication service at `https://auth.plytix.com`. Every other request goes to `https://pim.plytix.com`, under `/api/v1` or `/api/v2`.

## Send the token

Send the returned token in the `Authorization` header of every request, with a space after `Bearer`. Requests and responses on V1/V2 use JSON, so set the content headers as well:

```http
Content-Type: application/json
Accept: application/json
Authorization: Bearer your_access_token
```

Tokens expire after 15 minutes. When a token expires, or the API can't verify it, requests using it return `401` and you need to request a new token with the same exchange.

## Make your first request

With a token, you can read your catalog. This product search returns the first five products and their labels, which is enough to confirm that the token, the host, and your credentials all work:

```bash
curl --request POST \
  --url https://pim.plytix.com/api/v1/products/search \
  --header 'Authorization: Bearer <access_token>' \
  --header 'Content-Type: application/json' \
  --header 'Accept: application/json' \
  --data '{
    "attributes": ["label"],
    "pagination": { "page": 1, "page_size": 5 }
  }'
```

A `200` response has up to five products in `data`, each with its `id`, `sku`, and the attributes you asked for, and a `pagination` object whose `total_count` is the number of products in your account:

```json
{
  "data": [
    {
      "id": "<product_id>",
      "sku": "GF-Basket",
      "attributes": { "label": "Gift basket" },
      "num_variations": 3
    }
  ],
  "pagination": {
    "count": 1,
    "order": null,
    "page": 1,
    "page_size": 5,
    "total_count": 1
  }
}
```

If the request fails, check the status code:

| Status code | What to do |
|---|---|
| `401` | The token is missing, malformed, or expired. Check the `Authorization` header (`Bearer`, a space, then the token), request a new token, and send the request again. |
| `403` | The token is valid, but these API credentials aren't allowed to do this. Ask an administrator of your Plytix account to check the credentials on the **API** tab. |
| `422` | The search body isn't valid, for example a `page_size` over `100`. The response says which field to fix. |

To read the rest of the catalog, increase `page` until you've read `total_count` products. See [Pagination](/reference/v1-v2/pagination) and [Filtering and search](/reference/v1-v2/filtering-and-search).

## Error responses

If the token request fails, you get one of the following:

| Status code | Meaning |
|---|---|
| 400 BAD REQUEST | The request body is malformed. Check the request and try again. |
| 401 AUTH FAILED | The API key or password isn't valid. |

A `401` from the token request looks like this:

```json
{
  "error": {
    "msg": "Bad api_key or api_password: Credentials not valid",
    "errors": [
      {
        "field": "http_status_code",
        "msg": 401
      }
    ]
  }
}
```

<Callout type="info" title="Credentials are tied to an environment">
  The API key and password you issue work only against the authentication service for the environment that issued them. If a valid-looking key returns `401`, check that you're calling the right host.
</Callout>

See [Errors and status codes](/reference/v1-v2/errors-status-codes) for the error format used across V1/V2.
